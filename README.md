# SnapView

윈도우용 **화면 캡처 + 주석 편집 + 이미지 뷰어**. .NET 8 / WPF (C#), 외부 라이브러리 없음.

트레이에 상주하면서 전역 단축키로 캡처하고, 바로 주석을 얹거나 뷰어로 본다.
릴리스 단일 exe 는 **약 1.4MB**.

만든 곳 — **9to6blog** https://9to6blog.com

## 기능

### 캡처

| 동작 | 기본 단축키 |
|---|---|
| 영역 캡처 (얼린 화면 위에서 드래그) | `Alt+Shift+S` |
| 전체 화면 (모든 모니터) | `Alt+Shift+F` |
| 활성 창 | `Alt+W` |
| 현재 모니터 | 트레이 메뉴 |
| 영역 녹화 시작 / 종료 | `Alt+Shift+R` |
| 전체 화면 녹화 시작 / 종료 | `Alt+Shift+G` |
| 활성 창 녹화 시작 / 종료 | `Alt+Shift+T` |
| 현재 모니터 녹화 | 트레이 메뉴 |

`놓은 뒤 조절` 설정이 켜져 있으면 전체 화면 캡처도 모든 모니터가 선택된 상태로
오버레이가 열리며, 액션 바의 `자석 맞춤`을 누르면 선택 사각형 자체가 실제 콘텐츠
경계로 자동 변경된다. 바뀐 영역을 확인한 뒤 그대로 확정하면 된다.

영역 선택 오버레이:

- **드래그** — 영역 선택. 실시간으로 픽셀 크기 표시
- **클릭** — 커서 아래 창을 통째로 (창 테두리를 점선으로 미리 보여 줌)
- **십자 안내선** — 커서를 지나는 점선이 화면 끝까지 이어진다. 잡고 싶은 대상의
  모서리에 선을 맞춰 놓고 드래그하면 딱 떨어진다. 어두운 실선 위에 밝은 점선을
  겹쳐 그려서 배경이 밝든 어둡든 보인다(설정에서 끌 수 있음)
- **픽셀 돋보기** — 커서 주변 11×11 확대 + 좌표 + 색상 `#RRGGBB`
- **우클릭 = 색상 복사** — 커서 아래 색이 `#RRGGBB` 로 클립보드에 들어간다.
  돋보기 줄에 "복사됨" 이 떴다가 마우스를 움직이면 원래 표시로 돌아간다.
  (취소는 ESC. 예전에는 우클릭도 취소였다)
- **안내 막대는 커서가 다가오면 화면 반대쪽(위↔아래)으로 비켜난다.** 안내가 가리는
  자리를 캡처해야 할 때가 있다 — 숨겨 버리면 처음 쓰는 사람이 안내를 못 보니,
  비켜나는 것으로 두 요구를 다 지킨다. 드래그를 시작하면 그때는 사라진다.
- **오버레이를 닫는 키(Enter·Space·E·C·S·ESC)는 뗄 때 처리한다.** 누를 때 처리하면
  닫힌 직후의 키 뗌이 원래 보고 있던 앱으로 들어간다 — 영상을 틀어 놓고 스페이스로
  확정하면 그 뗌이 플레이어에 닿아 재생이 멈췄다. 방향키(미세 이동)만 반복이 필요해서
  누름에서 처리한다. 오버레이가 열리기 전부터 눌려 있던 키의 뗌은 무시한다
  (전역 단축키 Alt+Shift+S 의 S 가 "저장" 이 되면 안 되니까).
- **놓은 뒤 조절** — 모서리 8곳을 잡아 크기 조정, 안쪽을 끌어 이동,
  방향키 1px(Shift 10px), `Ctrl`+방향키로 크기 조절
- **Esc 한 번으로 캡처 전체 취소** — 영역을 드래그한 뒤에도 선택을 지우고 다시 고르는
  단계로 돌아가지 않고, 캡처 오버레이를 닫는다. 툴바 버튼에 포커스가 있어도 동일하다.
- **자석 맞춤** — 영역을 대략 잡은 뒤 액션 바의 `자석 맞춤` 또는 `M`을 누르면,
  선택 안의 흰색·검은색·투명·단색 바깥 여백과 긴 사각 콘텐츠 경계를 분석해
  **캡처 선택 사각형 자체를 자동으로 줄인다.** 맞춰진 그 영역이 편집기·복사·저장으로 넘어간다.
  SNS 화면에서는 흰 바깥 여백보다 가운데 미디어 카드의 긴 사각 경계를 우선하므로,
  위 계정·팔로우 머리글과 아래 하트·댓글·공유 줄은 빼고 카드 내부 자막은 보존한다.
  미디어 카드가 선택 영역의 맨 위나 1px 안쪽에 붙어 한 변이 보이지 않는 경우도,
  나머지 세 경계가 확인되면 선택 끝을 카드 경계로 보완해 아래 본문 UI를 제외한다.
- 드래그와 조절점은 가까운 창·모니터·긴 콘텐츠 경계에도 붙는다. 이 보조 스냅만
  잠시 풀고 싶을 때는 드래그 중 `Alt`를 누른다. 영역을 새로 그릴 때는 움직이는
  끝점뿐 아니라 좌·우·위·아래 네 변을 계속 다시 검사하므로 어느 방향으로 드래그해도 붙는다.
- **Space는 항상 파일 저장** — 캡처 영역을 선택한 뒤에는 자석 맞춤 등 어떤 툴바 버튼에
  포커스가 남아 있어도 Space를 떼면 선택 영역을 파일로 저장한다. 마지막 버튼을 다시
  실행하지 않으며, 캡처 후 복사·뷰어 열기 설정과 관계없이 `저장` 버튼과 같게 동작한다.
  녹화 영역 선택에서는 기존대로 녹화를 시작한다.
- 액션 바 — `편집(E)` `복사(C)` `저장(S · Space)` `자석 맞춤(M)` `확인(Enter)` `취소(ESC)`.
  **무엇 때문에 띄웠는지에 따라 단추가 달라진다.** 녹화하려고 띄운 창에 편집·복사·저장이
  떠 있으면 무엇을 누르라는 건지 알 수가 없다 — 그때 할 수 있는 일은 시작하거나 그만두거나
  둘뿐이라 `● 녹화 시작` 하나만 남긴다.
  `확인` 의 설명은 **지금 설정으로 실제로 무슨 일이 일어나는지**를 그대로 적는다
  ("파일로 저장 + 클립보드에 복사") — "설정대로 처리" 라고만 하면 옆의 `저장` 과
  무엇이 다른지 알 수가 없다.
  **모니터 하나 안으로 가둔다** — 가상 화면 안으로만 가두면 안 된다. 모니터 크기가 서로
  다르면 가상 화면에 어느 모니터에도 속하지 않는 빈 구역이 생기고(2560×1440 옆에
  1920×1080 을 붙이면 오른쪽 아래 360줄이 그렇다), 화면 아래쪽에서 영역을 고르면 막대가
  거기 놓여 아무 데도 안 보였다. 크기 표시 말풍선도 같은 규칙을 쓴다
  (`ViewMath.ClampInto`)

**창 단위 캡처는 3단계로 시도한다:**

1. `Windows.Graphics.Capture` — 위에 겹친 창이 안 찍히고, 하드웨어 가속 창도 검게 안 나온다.
2. `PrintWindow(PW_RENDERFULLCONTENT)` — 창에게 직접 그리게 시킨다.
3. 화면에서 창 영역만 잘라내기 (마지막 수단)

각 단계는 결과가 "전부 같은 색"이면 실패로 보고 다음으로 넘어간다.

### 주석 편집기

캡처 직후, 뷰어의 **편집** 버튼, 또는 트레이 → 클립보드 이미지 편집으로 연다. `F1` 을 누르면 단축키가 한눈에 뜬다.

**`Ctrl+S` · 저장 버튼**은 설정한 기본 폴더·파일 이름 규칙·이미지 형식으로 바로 저장한다.
같은 편집창에서 다시 저장하면 해당 파일을 갱신한다. 글자 입력 중에도 입력한 내용을 포함하며,
저장 후 추가로 수정하지 않았다면 닫을 때 저장 확인을 다시 띄우지 않는다.
경로나 형식을 직접 고르려면 저장 버튼을 우클릭해 **다른 이름으로 저장**을 선택한다.
레이어를 유지하는 프로젝트 저장은 기존처럼 `Ctrl+Shift+S`다.

| 도구 | 키 | 도구 | 키 |
|---|---|---|---|
| 선택·이동 | `V` | 텍스트 | `T` |
| 화살표 | `A` | 순서 번호 | `N` |
| 직선 | `L` | 모자이크 | `M` |
| 사각형 | `R` | 흐림 | `B` |
| 타원 | `O` | **자르기** | `C` |
| 펜 | `P` | **영역**(부분 복사·잘라내기) | `S` |
| 형광펜 | `H` | 자동선택 · 스포이드 | `W` · `I` |
| **강조** | `Shift+L` | **돋보기** | `Shift+M` |
| **번호+화살표** | `Shift+N` | 지우개 · 픽셀지우개 | `E` · `Shift+E` |
| 채우기 토글 | `F` | 팔레트 색 | `1`~`8` |
| 좌우 · 상하 뒤집기 | `Shift+H` · `Shift+V` | 90° 회전 | `Ctrl+R` · `Ctrl+Shift+R` |
| **이미지 크기 조절(확대 교체)** | 이미지 메뉴 | | |

**리본은 세 줄이다.** 1줄은 도구, 2줄은 어느 도구에나 통하는 색·굵기·투명도·점선·그림자·혼합, 3줄은
**지금 도구(또는 고른 주석)에만 뜻이 있는 것** — 글자면 글꼴·정렬, 모자이크·흐림·강조면 세기와 **모양**,
돋보기면 배율, 번호면 다음 번호, 자르기면 비율 프리셋과 폭·높이, 영역이면 복사·잘라내기. 3줄은 내용이
바뀌어도 높이가 같아서 화면이 안 흔들린다. 주석을 고르면 색·굵기·글꼴 같은 칸이 **그 주석의 값으로**
바뀐다 — 예전엔 빨간 화살표를 골라도 색칸은 직전에 쓰던 파랑에 체크돼 있었다.

**모자이크·흐림·강조는 사각형 말고도 된다.** 타원과 도형 갤러리 29종을 그대로 가리개 모양으로 쓴다
(가리기 영역을 도형 윤곽으로 오려 내므로 조절점·이동·회전은 사각형과 같다). 끌어서 크기를 맞추는 동안은
원본을 1/4 로 줄여 계산해 8K 캡처에서도 끊기지 않고, 손을 떼면 정밀하게 다시 계산한다.

**글자**는 확정한 뒤에도 **더블클릭으로 다시 편집**한다. 입력칸은 실제 글꼴·색·바탕으로 보이고,
오른쪽 조절점을 끌어 폭을 정하면 그 폭에서 자동으로 줄이 바뀌며 왼쪽·가운데·오른쪽 정렬을 고른다.
화살촉은 채움·열림·점 세 가지, 점선은 대시·점·일점쇄선 세 무늬. 형광펜은 **곱하기 합성**이 기본이라
흰 종이는 노랗게 되고 글자는 검게 남는다.

**끌기 보조**: `Shift` 정사각형·45°(갤러리 도형도), `Alt` 누른 자리를 가운데로, `Ctrl+끌기` 복제해서 옮기기,
`Alt+끌기`(옮길 때) 스냅 끄기. 여럿을 고르면 무리 전체 테두리의 조절점으로 **함께 크기를 바꾼다**.
조절점·회전 손잡이 위에서는 커서가 바뀌고, 집을 수 있는 주석은 살짝 테두리가 뜬다. 상태바에 커서 좌표와
그리는 중·고른 것의 크기가 나온다.

**보기**: `Ctrl+휠` 은 커서 아래 그림 점을 고정한 채 확대하고, 창에 맞춤(`Ctrl+Shift+0`)은 작은 그림도 키운다.
가운데 버튼이나 `Space+끌기` 로 화면을 옮기고, 200% 부터는 픽셀을 또렷하게 보여 준다. 그림 바깥 여백을
클릭하면 그리기가 아니라 확정·선택 해제다(예전엔 가장자리에 0픽셀 도형이 생겼다).

**잃어버리지 않는다.** 편집한 게 있으면 `Esc`·X 로 닫을 때 완료/버리기/계속을 묻고, 8초마다 복구 파일
(`%LocalAppData%\SnapView\recover.snapview`)을 몰래 써 두었다가 앱이 죽었으면 다음에 열 때 이어서 할지
묻는다. 화살표 키 이동·색·굵기·글꼴·레이어 숨김·잠금·이름까지 전부 `Ctrl+Z` 로 되돌리고, 연타는 한 칸으로
묶인다(`Ctrl+Shift+Z` 도 다시실행). 실행취소가 붙드는 그림은 512MB 예산 안에서만 남긴다. 복사에 실패하면
실패했다고 말한다. 창 자리·크기·마지막 도구·최근 색 여섯 칸을 기억하고, 제목에 프로젝트 이름과 `*` 가 붙는다.

**꾸며서 내보내기**(아래 줄)는 여백·배경(단색·그라데이션)·그림자·둥근 모서리·워터마크를 입혀 저장하거나
복사한다. 저장할 때 원본 DPI 를 그대로 둔다(예전엔 늘 96 으로 바뀌었다).

## 녹화 · 재생

트레이 → `녹화` 하위 메뉴에서 **영역 고르기 · 전체 화면 · 현재 모니터 · 활성 창** 중 고른다.
찍는 영역이 있는 모니터 구석에 작은 조종 막대가 뜬다 (경과 시간 · 장수 · **실측 fps** ·
잠깐 쉬기 · 정지 · 취소, 끌어서 옮길 수 있음). **막대와 테두리는 영상에 안 찍힌다** —
`SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` 로 캡처에서 빼 두므로 전체 화면을 찍어도 남지 않는다.
취소는 두 번 눌러야 한다(정지 바로 옆이라 한 번에 30분짜리를 날리면 안 된다). 버린 녹화물은 휴지통으로 간다.

단축키는 `Alt+Shift+R`(영역) · `Alt+Shift+G`(전체 화면) · `Alt+Shift+T`(활성 창) — 전부 토글. 녹화 중에는 찍고 있는 영역을 **빨간 점선이
깜빡이며 감싼다** — 점선이 흐르기까지 해야 정지 화면과 구분이 된다. 테두리는 영역
바깥에 **물리 픽셀로** 그리고(배율이 150% 인 모니터에서도 영역과 딱 맞는다) 클릭이 통과해서
그 안에서 하던 일을 계속할 수 있다.

**잠깐 쉴 수 있다.** 막대의 ❚❚ (또는 트레이 메뉴, 막대에 포커스가 있을 때 Space). 쉬는 동안은
화면도 소리도 안 들어가고 시계도 멈춘다 — 다시 찍으면 쉰 시간이 없었던 것처럼 이어진다.
설정에서 **시작 전 세기**(0~10초)를 켜면 영역 한가운데에 3·2·1 을 보여 준 뒤 시작한다(세는 동안
녹화 키를 다시 누르면 취소). 커서를 넣을지도 녹화 설정에 따로 있다(기본 켬).
영역을 고르는 중에는 다른 녹화 키가 먹지 않는다 — 예전엔 얼린 오버레이 화면을 찍기 시작했다.

시작음과 종료음이 **다르다**. 시작은 낮은 음에서 높은 음으로, 종료는 그 반대. 화면을
안 보고 단축키만 눌러도 켠 건지 끈 건지 알 수 있어야 하기 때문이다.

**소리도 같이 담는다.** 마이크가 아니라 지금 스피커로 나가는 시스템 소리(WASAPI 루프백)
— 영상·게임·회의 소리가 화면과 같이 들어간다. AAC 로 인코딩해 같은 MP4 에 넣는다.
소리를 못 잡아도 영상 녹화는 그대로 이어진다(로그에 남는다).

소리 덩어리는 **장치가 준 시각(QPC)대로** 트랙에 놓는다. 루프백은 조용할 때 패킷을 아예 안 주는데,
시각을 안 보고 뒤에 이어 붙이기만 하면 조용한 구간 뒤의 소리가 앞당겨진다. 빈 곳은 무음으로 메우고
겹치면 앞부분을 버린다. 96/192kHz 장치는 48kHz 로 바꿔서 담고(직선 보간), 5.1·7.1 은 채널 배치를
지켜 스테레오로 줄인다(센터는 양쪽에, 저음은 뺀다). 헤드폰을 뽑는 등 장치가 바뀌면 새 기본 장치에
다시 붙는다 — 끊긴 동안은 무음이고 완료 알림에 "소리 포함(중간에 끊김)" 으로 남는다.
MP4 를 못 열어 GIF 로 물러서면 소리 장치도 바로 놓는다(안 놓으면 큐만 시간당 1GB 넘게 쌓였다).

녹화 시작음과 "녹화 시작" 알림은 **녹화기를 켜기 전에** 낸다. 루프백은 스피커로 나가는 소리를
통째로 담기 때문에, 켠 뒤에 내면 시작음이 영상 맨 앞에 그대로 들어간다. 시작음은 다 날 때까지
기다렸다가(약 0.2초) 그 뒤에 소리 받기를 시작한다. 종료음은 파일을 닫은 뒤에 나므로 안 담긴다.

설정에서 **형식**(MP4 / GIF), **초당 장수**(1~120, 기본 60), **소리 담기**, **커서 포함**,
**시작 전 세기**, **시작음·종료음**(캡처음과 따로 켜고 끄고 크기를 정한다), **이름 규칙**(`{0}` 시각,
`{1}` 무엇을 찍었는지 — 전체 화면·모니터·영역·창 제목)을 고른다.
초당 장수는 막대로 끌거나 숫자를 직접 쳐 넣는다. GIF 는 간격 단위가 1/100초라 **50 이 한계**고,
30fps 처럼 나누어떨어지지 않는 값은 반올림 오차를 다음 장에 넘겨 전체 길이를 맞춘다.

**찍는 일은 전용 스레드에서 한다.** 예전에는 화면 타이머로 돌렸는데, 그 타이머는 창
그리기·입력에 밀리는 낮은 순위라 60 을 골라도 25장쯤에서 막혔다. 지금은 시계를 직접 보며
도는 스레드가 찍고(윈도우 타이머 눈금도 녹화하는 동안만 1ms 로 당긴다), 화면 쪽에는
다 찍고 나서 알려 주기만 한다. 240×180 이면 120장, 1920×1080 이면 50장 남짓 나온다.

**높게 잡는다고 그만큼 나온다는 보장은 없다.** 넓은 영역일수록 한 장 찍는 데 오래 걸린다.
못 따라가면 그냥 덜 찍히는데, 장마다 **찍힌 시각을 그대로 적으므로 영상 길이는 실제 시간과
맞는다** — 예전에는 정해 둔 간격대로 쌓아서, 덜 찍힌 만큼 영상이 빨리 감겼다.
실제로 몇 장이 담기고 있는지는 녹화 막대에 나오고, 끝나면 알림에도 적힌다.

**H.264 MP4** 로 담는다. Media Foundation 의 SinkWriter 를 COM 으로 직접 부른다 —
WinRT C# 프로젝션을 쓰면 이 기능 하나에 실행 파일이 25MB 불어나기 때문이다.
인코더가 없는 환경에서는 움직이는 GIF 로 물러선다(로그에 남는다).

찍은 프레임을 모아 뒀다가 저장하지 않고 **즉시 파일로 흘려 보낸다**. 1920×1080 한 장이
8MB 라 10fps 로 30초만 찍어도 2GB 가 넘는다. GIF 는 도중에 앱이 죽어도 그때까지가 남지만,
**MP4 는 마무리(moov)를 써야 열린다.** 그래서 화면 잠금·절전·로그오프·모니터 구성 변경 때는
먼저 저장하고 멈추며, 화면 스레드 밖에서 예외로 죽을 때도 파일부터 닫는다. 전원이 끊기는 경우만 못 막는다.

**정지는 뒤에서 마무리한다.** 찍는 스레드가 멈추길 기다리고 moov 를 쓰는 데 느린 드라이브에서는
몇 초가 걸리는데, 그동안 막대에 "저장 중…" 을 보이고 화면은 굳지 않는다. 마무리가 실패하면(디스크가
찼거나 저장 폴더가 사라졌거나) "녹화 완료" 가 아니라 **"녹화 실패"** 로 알린다 — 예전엔 열리지 않는
파일을 완료라고 했다. 정지 뒤 폴더가 사라져 있어도 앱이 죽지 않는다.

화면은 BitmapSource 를 거치지 않고 **버퍼를 재사용해** 떠서 바로 NV12 로 바꾼다(포인터로 두 줄씩).
예전엔 프레임마다 8MB 를 새로 잡고 Bgr32→Bgra32 변환까지 한 번 더 해서 초당 장수를 갉아먹었다.

**녹화도 캡처와 같은 네 가지로 고른다** — 영역 · 전체 화면 · 현재 모니터 · 활성 창.
전체 화면과 활성 창은 전용 단축키가 따로 있어서 영역을 고르는 단계 없이 바로 시작한다.
찍는 중에는 **어느 녹화 키를 눌러도 멈춘다** — 무엇으로 시작했는지 기억해 뒀다가 같은 키를
찾아 눌러야 한다면 그게 더 이상하다. 활성 창은 <b>누른 순간의 자리</b>를 찍고 창을 따라다니지
않는다(따라다니면 창을 옮길 때마다 영상이 덜컥거려서 오히려 못 쓴다).

## 컷 · 배속 (가벼운 편집)

재생 창의 `편집` 토글을 켜면 재생 막대 위에 편집 줄이 열린다.

- **⟦ 시작 · 끝 ⟧** — 지금 재생 위치를 구간의 시작/끝으로 찍는다. 안 찍으면 전체가 구간이다.
- **배속** — 0.25× ~ 4×. 0.5× 가 슬로우 모션.
- **MP4로 내보내기** — 저장 폴더에 `스냅뷰_원본이름_컷_시각.mp4` 로 **새 파일**을 만든다.
  원본은 절대 건드리지 않는다. 내보내는 중에 같은 단추를 다시 누르면 취소.

**다시 인코딩한다.** 압축을 안 풀고 이어 붙이는 방식(무손실 컷)은 키프레임 자리에서만
자를 수 있어 "여기서부터 여기까지" 가 안 맞는다 — 화면 녹화물은 짧아서 정확한 가위질이
더 중요하다. 대신 디코딩한 NV12 를 RGB 로 풀지 않고 그대로 인코더에 되넣어(`AddNv12`)
색 변환이 한 번으로 끝난다. 되읽기도 인코딩과 같은 방식으로 Media Foundation 의
SourceReader 를 COM vtable 로 직접 부른다(`Native/VideoReader.cs`).

**소리는 1×일 때만 담는다.** 느리게/빠르게 한 소리는 음정이 틀어져 쓸 수 없고,
음정을 지키는 시간 늘이기는 이 앱의 몫이 아니다.

되읽기 함정 둘 (실제로 걸렸던 것):
- **디코더 프레임은 표시 크기가 아니라 코딩 크기다.** H.264 는 16의 배수로 부호화해서
  548×466 영상의 표면은 560×480 이고 줄 간격(피치)은 다시 576 처럼 더 클 수 있다.
  `ContiguousCopyTo` 는 피치 여유만 벗기고 **코딩 크기는 그대로** 주므로, 표시 크기로
  읽으면 줄이 밀린 줄무늬가 된다 — 실제 녹화물이 그렇게 깨졌다. `Lock2D` 로 피치를 받아
  표시 크기만 걷어 내고, UV 면은 표시 높이가 아니라 **코딩 높이**(전체÷피치÷1.5) 뒤에서
  읽는다. 단색 프레임 검사는 이걸 못 잡는다 — 사분면 패턴으로 가장자리까지 확인한다.
- `ReadSample` 깃발의 **0x1 은 ERROR 고 끝은 0x2 다.** 헷갈리면 끝을 영영 못 알아보고
  무한 루프에 빠진다.

## 재생

뷰어는 **움직이는 GIF**(프레임별 간격 그대로)와 **동영상 파일**(mp4·mkv·avi·mov·webm 등)을
재생한다. 재생 막대에 앞뒤 건너뛰기 · 한 장씩 이동 · 위치 · 경과/전체 시간 · **장 번호** ·
이 장면 저장 · 소리 · 속도(0.25×~4×) · 반복이 있다. **반복은 기본으로 켜져 있다** — 캡처로 찍은
영상은 대개 짧아서, 끝에서 멈춰 서 있는 것보다 계속 도는 편이 어디를 다시 볼지 고르기 좋다.

**재생기(MediaElement)를 안 쓴다.** MediaElement 가 그리는 그림은 `RenderTargetBitmap` 에
안 잡혀서 "이 장면 저장" 을 만들 수가 없다. 대신 `MediaPlayer` 를 직접 쥐고
`DrawingContext.DrawVideo` 로 그리는데, 이건 화면에 칠하는 것과 똑같은 그림을 그대로 떠낼 수 있다.
뜬 장면은 주석 편집기로 넘어간다 — 자르고 표시하고 저장하는 건 이미 거기가 다 한다.

**몇 번째 장인지 보여 준다.** 재생기는 장 수도 초당 장수도 안 알려 줘서, MP4 계열은 파일의
`moov/trak/mdia` 박스를 직접 읽어 장 수와 길이를 구한다(`Core/VideoInfo.cs`). 그래서 한 장씩
정확히 옮길 수 있다. 다른 컨테이너는 시간만 보여 주고 장 단위 이동 단추는 흐려진다.

**재생 위치 막대는 아무 데나 눌러도 그 자리로 간다.** 예전에는 손잡이를 잡고 끄는 동안에만
반응해서, 막대를 눌러도 잠깐 움직였다가 곧 제자리로 돌아왔다 — 손잡이를 정확히 집어야만
옮길 수 있는 것처럼 보인 이유다. 지금은 코드가 넣은 값이 아니면 전부 사용자가 민 것으로 본다.

재생 중에는 같은 키가 다른 뜻이 된다 — 영상에서 `→` 가 다음 파일로 넘어가면 곤란하니까.
**재생 키는 설정에서 전부 바꿀 수 있고**, 건너뛸 시간도 초 단위로 정한다.

| 키(기본값) | 재생 중 | 그림 볼 때 |
| --- | --- | --- |
| `Space` | 재생 / 멈춤 | 다음 |
| `←` `→` | 정한 시간만큼 뒤/앞 (기본 5초) | 이전 / 다음 |
| `Ctrl+←` `Ctrl+→` | 한 장 뒤/앞 | — |
| `↑` `↓` | 소리 크게/작게 | 위아래로 밀기 |
| `M` | 소리 끄기 | — |
| `L` | 반복 | — |
| `Shift+S` | 이 장면을 저장 폴더에 저장 | — |
| `PageUp` `PageDown` | 이전 / 다음 파일 | 이전 / 다음 |

한 장 이동은 `Ctrl` 을 붙인 것이라, 키를 맞춰 볼 때 **거들 키를 정확히** 본다. `←` 로 지정해
둔 것이 `Ctrl+←` 까지 먹으면 한 장씩 옮기려던 사람이 통째로 건너뛰게 된다.

**마우스 휠은 재생 중에 소리 크기다.** 영상에는 확대·축소가 없으니 그 자리에서 제일 자주
쓰는 것을 준다(그림을 볼 때는 확대·축소 그대로).

**재생 키는 누구에게 포커스가 있든 먼저 듣는다.** 단추를 한 번 누르면 그 단추가 키보드
포커스를 쥐어서, 그다음 Space 가 재생/멈춤이 아니라 그 단추를 또 눌렀다. 터널링 단계에서
먼저 가로챈다 — 글자를 넣는 칸과 목록 상자만 예외다.

**이 장면 저장** — 누른 그 순간의 화면을 설정한 저장 폴더·형식으로 저장한다. 재생을 멈추지
않는다. 세워 놓고 고르고 싶으면 한 장씩 옮기는 키가 따로 있다.

이름은 캡처와 <b>다른 규칙</b>을 쓴다 — `스냅뷰_원본이름_날짜시각`. 날짜만 있으면 나중에
폴더를 열었을 때 무엇을 찍은 것인지 알 수 없다. 규칙은 설정의 `FrameNamePattern` 이고
`{0}` 이 시각, `{1}` 이 원본 이름이다. 원본 이름을 모를 때는 그 자리와 함께 남는 밑줄도
정리한다(안 그러면 `스냅뷰__2026-…` 처럼 밑줄이 두 개 붙는다).

저장했다는 알림은 **잠깐 떴다 사라지는 쪽지**로 영상 위에 띄운다. 재생 막대에 글자를 밀어
넣었더니 이름이 긴 파일에서 가운데 위치 막대가 통째로 밀려나 사라졌다 — 배치에 끼지 않는
층에 띄우고 1.8초 뒤에 스르르 지운다.

**영상 위 마우스** — 두 번 누르면 재생/멈춤, 끌면 창이 따라온다(재생기에서 흔히 그렇게
한다. 영상에는 확대가 없으니 그림처럼 밀어 봐야 밀 것이 없다). 끌기는 **실제로 움직이기
시작할 때** 걸린다 — 누르자마자 `DragMove` 를 부르면 윈도우의 창 이동 루프로 들어가 버려서
두 번 누르기가 그 루프에 먹힌다. 그림을 볼 때는 예전 그대로 두 번 누르면 전체 화면,
끌면 그림 밀기다.

**폴더 이어 보기** — 반복이 꺼져 있으면 영상이 끝날 때 같은 폴더의 다음 영상으로 넘어간다.
사진은 건너뛴다. 반복이 켜져 있으면 그쪽이 먼저다.

**그림 창과 재생 창은 따로 뜬다.** 한 창에서 돌려쓰면 영상을 열 때 보던 그림이 사라지고
그림을 열 때 보던 영상이 멎는다. 창을 만들 때 종류가 정해지고 바뀌지 않으며, 폴더를 훑는
목록도 종류별로 갈라 둔다 — 그림 창은 그림만, 재생 창은 영상만 지나간다. 그림 창에 영상을
떨구면 창을 갈아엎지 않고 재생 창으로 넘긴다.

**새 창 / 같은 창** 설정은 **영상에만** 적용한다. 새 창은 영상 둘을 나란히 놓고 볼 때 쓴다.
사진은 언제나 보던 창에 갈아 끼운다 — 폴더를 훑을 때마다 창이 하나씩 쌓이면 못 쓴다.

동영상 확장자도 윈도우 파일 연결에 등록된다. 설정에서 `기본 이미지 · 영상 앱으로 연결` 을
누르면 동영상 더블클릭으로도 열린다.

등록해 둔 것이 **낡았으면 시작할 때 스스로 다시 쓴다.** 앱이 자라면서 다룰 수 있는 확장자가
늘어나는데(동영상이 그랬다), 그림 ProgId 하나만 보고 "이미 등록됨" 이라고 하면 새 확장자는
영영 목록에 안 올라 mp4 를 SnapView 로 열 수가 없다. 등록한 적이 없으면 아무것도 하지
않는다 — 묻지도 않고 남의 목록에 끼어들지는 않는다.

**아이콘은 직접 그린다.** `▶ ❚❚ ↺ ↻ ⇋ ⇅ 🔊 ✓ ✕` 같은 특수문자는 글꼴마다 모양도 크기도
제멋대로라, 나란히 놓으면 어긋나고 어떤 PC 에서는 네모로 뜬다. 필요한 것만 `Geometry` 로
그려 두고(`App.xaml`), 선으로 그리는 것은 `Icon`, 속을 채우는 것(재생 삼각형 등)은
`IconSolid` 스타일을 쓴다. 편집기가 먼저 그렇게 했고 뷰어·오버레이도 같은 방식으로 맞췄다.

**리본 배치** — 줄마다 역할이 정해져 있다. 1줄 도구, 2줄 도형·색·스타일,
3줄 글꼴·가리기 세기. 창이 좁으면 접히는 대신 가로로 밀린다 — 폭에 따라
버튼 위치가 매번 달라지면 손이 기억을 못 한다.

배치를 눈으로 확인하려면 `SnapView.exe --shot 경로.png` — 편집기를 화면 밖에서
그려 PNG 로 떨군다. 개발용이라 평소 동작에는 관여하지 않는다.

**도형 갤러리** — 사각형 · 타원 · 삼각형 · 직각삼각형 · 마름모 · 오각형 · 육각형 ·
4각별 · 5각별 · 말풍선 · 블록 화살표 · 십자 · 하트. 전부 사각형 하나로 정해져서
조절점 8개로 똑같이 끌어 고친다.

**스포이드**(`I`) — 그림에서 색을 집는다. 한 번 집으면 쓰던 도구로 돌아간다.
**지우개**(`E`) — 지나간 <b>자리만</b> 판다. 주석을 통째로 지우지 않는다. 선 하나에
지우개를 대면 닿은 데만 뚫리고 나머지는 남는다. 도형·글자·번호도 마찬가지다.
지운 뒤에 새로 그린 것은 안 지워진다. 굵기 값이 지우개 크기다.
통째로 없애려면 레이어 목록에서 삭제하는 편이 빠르다.
**아무것도 안 스친 획은 버린다** — 빈 데를 문질렀는데 기록만 쌓이면 지우개가 아니다.
지운 자리는 레이어 목록에도 안 나온다(되돌리기는 `Ctrl+Z`).

**픽셀 지우개**(`Shift+E`) — 그림 자체를 투명하게 판다. 굵기만큼 지워지고,
PNG 로 저장하면 그 자리가 뚫린 채로 남는다.

**번호+화살표**(`Shift+N`) — 번호 원에 가리키는 화살표가 달린 것. 화살촉을 짚을 곳에
대고 끌면 번호 원이 딸려 나온다. 촉과 원을 각각 조절점으로 끌고, 번호는 `번호` 도구와
같은 순번을 이어 쓴다.

**자유 회전** — 도형·펜 획·글자·붙인 그림을 고르면 위쪽에 동그란 회전 손잡이가
달린다. 끌면 그 자리에서 돌고, `Shift` 를 누르면 15° 단위로 똑똑 끊긴다.
돌려 놓은 뒤에도 조절점·적중 판정이 돌아간 모양 그대로 동작한다.
(모자이크·번호·돋보기처럼 축이 서야 하는 것들은 손잡이가 없다)

**펜 일자 긋기** — `Shift` 를 누른 채 끌면 획이 시작점 기준 가로/세로로만 나간다.

**정렬·균등 간격** — 여럿을 골라 두고 스타일 줄의 `정렬 ▾`. 왼쪽/가운데/오른쪽·
위/가운데/아래 맞춤과, 셋 이상일 때 가로/세로 간격 고르게. 기준은 캔버스가 아니라
**골라 둔 것들의 전체 테두리**다.

**스마트 가이드** — 주석을 끌면 다른 주석·캔버스의 가장자리·가운데에 가까워질 때
분홍 기준선이 뜨면서 착 붙는다. `Alt` 를 누른 채 끌면 스냅 없이 자유롭게 움직인다.

**점선 · 양촉** — 스타일 줄의 토글 둘. `점선` 은 테두리·선·펜 획을 점선으로,
`양촉` 은 화살표 양 끝에 촉을 단다(구간 표시용).

**캔버스 여백 늘리기** — `이미지 ▾` 메뉴. 그림은 그대로 두고 **공간만** 붙인다
(크기 조절은 그림을 늘린다는 점이 다르다). 채울 색은 투명/흰색/검정/지금 색.
투명으로 늘려 PNG 로 저장하면 여백이 뚫린 채로 남는다.

**프로젝트(.snapview)** — 아래 작업 줄의 `프로젝트 ▾`. PNG 로 합치면 주석을 다시 못
만지지만, 프로젝트로 저장하면 **레이어 살린 채** 남는다 — 열면 그대로 이어서 편집.
속은 JSON 하나(바탕 그림 + 주석 값들, 버전 표기)라 형식이 자라도 옛 파일을 읽는다.
모든 주석 종류가 왕복되는 것을 자체 검사가 하나하나 확인한다.

**레이어 이름 · 잠금** — 레이어 행을 우클릭: `이름 바꾸기`(비우면 다시 종류로 부른다),
`잠금`(캔버스에서 안 집히고 옮기거나 지울 수 없다 — 목록에 "(잠김)" 으로 표시),
`복제`, `삭제`.

**그라데이션 채우기** — 스타일 줄의 `그라데` 토글. 채운 도형이 위→아래로 옅어진다.

**혼합 모드** — 스타일 줄의 `혼합`(보통·곱하기·스크린·오버레이). 도형·붙인 그림을
바탕 그림과 픽셀로 직접 섞는다 — WPF 에는 혼합이 없어서 도형을 투명 위에 그린 뒤
바탕과 계산해 넣는다. 화면과 결과가 같은 길을 타고, 같은 모양이면 다시 계산하지
않는다(캐시). <b>바탕 그림하고만 섞인다</b> — 주석끼리는 안 섞인다.

**자동 선택(마술봉)** `W` — 클릭한 자리와 비슷한 색으로 <b>이어진</b> 영역을 고른다
(파랗게 물들어 보인다). 허용치는 "색 허용치" 칸. `Shift+클릭` 으로 영역을 더하고,
`Delete` 는 투명하게 지우기(배경 제거 — PNG 로 저장하면 뚫린 채 남는다),
`Enter` 는 지금 색으로 채우기, `ESC` 해제.

**대상 지우개** — 주석 <b>하나를 골라 두고</b> 지우개를 쓰면 그 주석만 파인다
(레이어 마스크 격). 아무것도 안 골랐으면 예전처럼 아래 전부를 판다.

**회전**(`Ctrl+R` / `Ctrl+Shift+R`)과 **캔버스 크기** — 주석도 같은 비율로 따라간다.
글자는 눕지 않고 자리만 옮긴다.

**레이어** — 오른쪽 목록. 눈 표시로 숨기고, 골라서 순서를 바꾼다.
`Ctrl+]` 앞으로 · `Ctrl+[` 뒤로 · `Shift` 를 더하면 맨 앞/맨 뒤.
목록에서도 `Ctrl`/`Shift`+클릭으로 여럿을 고를 수 있다(캔버스 선택과 같이 움직인다).
**＋ 그림** 단추로 다른 그림 파일을 불러와 레이어로 얹는다 — 캔버스보다 크면
알아서 안에 들어오게 줄여 놓는다. 편집할 원본을 여는 건 트레이의 `이미지 열기`.

**색** — 팔레트 끝의 🎨 로 색상판을 연다. 네모에서 선명함·밝기, 띠에서 색상을
고르고, `#RRGGBB` 로 직접 칠 수도 있다. 고른 색은 팔레트 옆 칸에 남는다.

**스타일** — 색·굵기 옆에 `투명도`(10~100%)와 `채우기`(F) 가 있다. 투명도는 지금
그리는 중인 것과 선택한 것에 바로 먹는다. **모자이크·흐림은 투명도를 안 받는다** —
반투명해지면 가린 내용이 비쳐서 가리는 의미가 없어지기 때문이다.

**글꼴** — 시스템에 깔린 글꼴을 목록에서 고른다. 목록은 각 글꼴로 보여 준다.
크기는 옆 슬라이더(10~80).

**필터** — 툴바의 `필터 ▾` 로 이미지 전체에 건다. 흑백 · 세피아 · 색 반전 ·
노이즈 · 밝게 · 어둡게 · 대비 높이기 · 선명하게 · 부드럽게. 주석은 그대로 위에
남고, `Ctrl+Z` 로 되돌아간다.

**그린 뒤 바로 확정되지 않는다.** 조절점이 달린 채로 남으니 끌어서 위치·크기를
맞춘 뒤 **Enter** 로 확정한다. `ESC` 로 버리고, 다른 곳을 누르거나 도구를 바꾸면
자동으로 확정된다.

**확정한 주석도 크기를 다시 바꿀 수 있다.** 선택 도구(`V`)로 고르면 조절점이
다시 붙는다 — 끌어서 고치고, `Ctrl+Z` 로 되돌린다. 색·굵기·투명도도 고른 채로
바꾸면 그 주석에 바로 먹는다.

**여러 개를 한꺼번에 고른다.** `Shift+클릭` 으로 넣었다 뺐다, 빈 곳을 끌면
올가미로 쓸어 담고, `Ctrl+A` 는 전부. 골라 둔 것들은 함께 끌려 오고, 방향키로
같이 밀리고, `Delete` 로 같이 지워지고, 색·굵기 같은 스타일도 한꺼번에 먹는다.

**복제와 복사.** `Ctrl+D` 는 골라 둔 주석을 살짝 어긋난 자리에 복제. `Ctrl+C` 는
주석을 골라 뒀으면 주석을 복사하고(`Ctrl+V` 로 붙여넣기, 번호는 다음 번호를 받는다),
아니면 예전처럼 결과물 이미지를 복사한다. 밖에서 그림을 복사해 오면 `Ctrl+V` 는
자연히 그림 붙여넣기로 돌아간다 — 판별은 클립보드에 남긴 표식으로 한다.

**그림자.** 스타일 줄의 토글. 도형·글자·화살표·펜이 캡처 배경에서 또렷이 떠 보인다.
모자이크·흐림(가리개)과 강조는 제외 — 배경의 일부처럼 보여야 하는 것들이다.

**강조(스포트라이트)** `Shift+L` — 끌어 잡은 영역만 원래 밝기로 남기고 밖을 어둡게
덮는다. "여기를 보라"의 가장 확실한 표현. 투명도 슬라이더가 그대로 어둡기 조절이다.

**돋보기** `Shift+M` — 클릭하면 그 자리를 동그란 창에 2배로 확대해 띄운다.
작은 점(확대할 곳)·원 안(창 옮기기)·원 가장자리(창 크기)를 각각 끌어 맞춘다.
어디를 확대했는지 가는 선이 이어 준다.

**텍스트 외곽선·바탕.** 글꼴 줄의 토글 둘. `외곽선`(기본 켬)은 글자 둘레의 얇은
검은 선 — 밝은 배경에서도 읽힌다. `바탕`은 글자 뒤에 라벨처럼 상자를 깐다.
글자색이 밝으면 어두운 상자, 어두우면 밝은 상자가 자동으로 붙는다.

- 사각형·타원·모자이크·자르기 → 모서리 8곳 조절점
- 화살표·직선 → 양 끝점 조절점
- 글자·번호·펜 → 이동만 (방향키로 미세 조정)

그 밖에:

- **자르기**: 남길 영역을 끌면 바깥이 어두워진다. Enter 로 실제로 잘리고,
  이미 얹어 둔 주석도 같이 옮겨진다. `Ctrl+Z` 로 되돌아간다.
- **자동 여백**: 자르기 도구에서 흰색·검은색·투명 레터박스를 찾아 조절 가능한
  자르기 상자로 표시한다. 확인 후 Enter 로 확정하며, 자르기 선은 가까운 긴 콘텐츠
  경계에 자석처럼 붙는다. `자석` 토글로 켜고 끄며 드래그 중 `Alt`를 누르면 잠시 풀린다.
- **텍스트 줄바꿈**: 입력 중 `Enter` 는 줄바꿈, `Ctrl+Enter` 로 입력을 마친다.
- **뒤집기**: 이미지와 주석이 함께 뒤집힌다. 글자는 거울 반전 없이 위치만 옮긴다.
- `Shift` 를 누른 채 그리면 45° 단위 / 정사각형
- `Ctrl+Z` 실행취소, `Ctrl+Y` 다시실행 (자르기·뒤집기도 되돌아간다)
- `Ctrl+휠` 확대·축소, 그냥 휠은 스크롤
- `Ctrl+C` 복사, `Ctrl+S` 다른 이름으로 저장, `Ctrl+Enter` 완료

주석 좌표는 전부 **원본 이미지 픽셀**로 들고 있다가 마지막에 원본 해상도로 합친다.
창을 줄여서 편집해도 결과물 화질이 떨어지지 않는다.

| 이미지 우클릭 | `주석 편집기로 열기` 메뉴 |
| `Ctrl+C` `Ctrl+S` `Ctrl+O` `Ctrl+E` | 복사 / 다른 이름으로 저장 / 열기 / 탐색기에서 보기 |
| `Delete` | 휴지통으로 |
| `F11`, 더블클릭 | 전체 화면 |
| 드래그 | 이미지 이동 |
| 가운데 클릭 | 100% ↔ 맞춤 토글 |

- **썸네일 줄**: 폴더의 모든 이미지를 아래에 늘어놓는다. 클릭하면 바로 넘어가고,
  현재 이미지가 항상 화면 안에 오도록 따라간다. 썸네일은 화면에 나타날 때 비로소
  읽으므로 폴더에 수천 장이 있어도 버틴다.
- 기본 배율 정책은 **창보다 클 때만 축소**. 작은 그림은 원본 크기 그대로 둔다.
- 설정한 배율(기본 300%)을 넘으면 보간을 끄고 픽셀을 또렷하게(도트 확인용).
- 파일 목록은 탐색기와 같은 **숫자 인식 정렬**(`img2` < `img10`).
- JPEG 의 EXIF 회전 정보를 반영한다. 투명 이미지는 체커보드 위에 그린다.

### 캡처 알림음

셔터 소리("찰칵")는 쓰지 않는다. 하루에 수십 번 나는 소리라 자동차 UI 처럼
**짧고 부드럽고 작은** 톤이어야 한다. 음원 파일 없이 그때그때 사인파를 합성한다 —
A5 기본음에 5도·옥타브를 약하게 섞고, 4ms 만에 열렸다가 지수적으로 잦아든 뒤
마지막 10ms 를 부드럽게 내려 '툭' 소리를 없앤다. 전체 길이 0.16초.

볼륨은 파형 진폭에 직접 녹여 넣는다(SoundPlayer 에 볼륨 조절이 없어서).
설정 창에서 크기를 바꾸고 **들어보기** 로 바로 확인할 수 있다. 기본 35%.

### 윈도우 이미지 뷰어로 연결

트레이 → **윈도우 이미지 뷰어로 연결...** 또는 설정 창 아래 버튼.

등록하면 파일 탐색기에서 이미지를 우클릭해 **SnapView 편집기로 열기**를 고를 수 있다.
기본 이미지 앱을 SnapView로 바꾸지 않아도 이 메뉴는 동작한다. Windows 11에서는 시스템
설정에 따라 **더 많은 옵션 표시** 안에 보일 수 있다.
상주 앱이 관리자 권한이라 탐색기의 일반 권한 요청을 직접 받을 수 없는 경우에도 별도
편집기 창으로 열리며, 그때 뜬 독립 뷰어의 상단 `편집` 단추도 그대로 동작한다.

윈도우의 이미지 처리기(WIC)와 재생 엔진(Media Foundation)이 다루는 범위를 그대로 따라간다 —
그림 30가지, 동영상 24가지. WebP · HEIC · AVIF · JPEG XL · 카메라 RAW 는 스토어 확장이
깔려 있으면 읽히고, 없으면 열 때 그렇다고 말해 준다(목록에서 미리 빼면 코덱이 있는 사람도
못 열게 된다). 전부 `HKCU` 라 관리자 권한이 필요 없다.

**목록에 없는 확장자도 일단 열어는 본다.** 그림으로 한 번, 안 되면 영상으로 한 번.
사용자가 굳이 골라서 연 파일을 "목록에 없다" 는 이유로 거절하는 건 도움이 안 된다.

그림과 동영상은 **서로 다른 ProgId** 로 등록한다. 하나로 묶으면 윈도우 기본 앱 화면에서
mp4 항목이 "이미지 파일" 로 뜨거나 아예 후보에 안 나온다.

윈도우 8 이후로는 **기본 앱을 프로그램이 직접 바꿀 수 없다**(UserChoice 가 해시로
보호된다). 그래서 "연결 프로그램" 목록과 기본 앱 설정 화면에 뜨게까지만 하고,
마지막 선택은 윈도우 설정에서 사용자가 한다. 등록을 지우는 것도 같은 메뉴에서.

## 이 PC 에 남는 것

**그림이나 영상을 캐시해 두지 않는다.** 썸네일은 화면에 보일 때 읽고 창을 닫으면 사라진다.
디스크에 남는 것은 `%APPDATA%\SnapView` 안의 **설정**과 **기록** 둘뿐이고, 기록에는 열어 본
파일의 경로가 들어간다. 설정 창 아래에서 무엇이 얼마나 쌓였는지 보고 기록만 지울 수 있다.

### 좌표계 (헷갈리기 쉬운 부분)

- **물리 픽셀** — 실제 화면. `PerMonitorV2` 덕분에 `GetSystemMetrics` / DWM 이 이 단위로 답한다.
- **비트맵 픽셀** — 얼린 화면 이미지 안의 좌표 = 물리 픽셀 − 가상 화면 원점.
- **DIP** — WPF 레이아웃 단위.

오버레이는 배경을 `Stretch=Fill` 로 깔아 두기 때문에, DPI 가 서로 다른 모니터가
섞여 있어도 `비트맵크기 / ActualWidth` 비율만 곱하면 정확히 대응된다.

뷰어의 배율은 **이미지 픽셀 : 화면 물리 픽셀** 비율이다. 즉 150% DPI 모니터에서도
"100%"는 진짜 1:1 이다. WPF 변환에 쓰는 값은 `배율 ÷ DPI배율`.

### WinRT 를 COM 으로 직접 부르는 이유

`Windows.Graphics.Capture` 를 C# 프로젝션으로 쓰면 TFM 을 `net8.0-windows10.0.22621.0`
으로 올려야 하고, 그러면 `Microsoft.Windows.SDK.NET.dll` **25MB** 가 딸려 온다.
API 하나 때문에 실행 파일이 1.4MB → 27MB 가 되므로 COM 으로 직접 호출한다.

IID 와 vtable 슬롯은 추측이 아니라 실제 프로젝션 어셈블리를 리플렉션으로 뜯어 확인한 값이다.
슬롯이 하나만 틀려도 프로세스가 즉사하므로 **자체 검사가 매번 진짜 창을 한 번 떠 본다.**

## 빌드

새 Windows 환경에서 도구 설치, 소스 복구, 검사와 배포를 이어 가는 순서는
[포맷 후 개발 환경 복구](POST-FORMAT-RECOVERY.md)를 참고한다.

```
build.bat              디버그 빌드
build.bat release      릴리스 단일 exe (dist\SnapView.exe)
build.bat installer    설치 프로그램 (setup\SnapView-Setup.exe)
build.bat selftest     GUI 없이 자체 검사 실행
build.bat icon         assets\app.ico 다시 생성
build.bat clean        빌드 산출물 정리
```

### 설치 프로그램

`build.bat installer` 는 본체를 먼저 publish 한 뒤, 그 exe 를 **리소스로 품은**
단일 설치 파일 `setup\SnapView-Setup.exe` (약 3MB) 를 만든다.

- 기본 설치 위치는 `C:\Program Files\SnapView` — **관리자 권한이 필요하다**
  (매니페스트가 권한 상승을 요구한다. 사용자 폴더에 넣고 싶으면 설치 화면에서 경로를 바꾼다)
- 바탕화면·시작 메뉴 바로가기, 자동 실행, **이미지 · 동영상 연결**을 설치 중에 고른다.
  파일 연결을 등록하면 탐색기의 **SnapView 편집기로 열기** 우클릭 메뉴도 함께 등록된다
- 연결 등록은 **본체와 같은 코드**(`Core/FileAssociation.cs`)를 부른다. 예전에는 설치기가
  같은 일을 따로 구현하고 있었는데, 그쪽이 그림 확장자만 등록하는 바람에 설치한 사람은
  mp4 를 SnapView 로 열 수가 없었다 — 본체는 "이미 등록됨" 으로만 보고 손대지 않았다.
  확장자 목록은 `Core/MediaKinds.cs` 한 군데에만 둔다
- 자기 자신을 `uninstall.exe` 로 복사하고 제어판(앱 및 기능)에 등록한다
- 이미 설치돼 있으면 "업데이트" 로 바뀌고, 실행 중인 SnapView 를 알아서 종료한다
- `/S` 조용히 설치, `/D=경로` 로 위치 지정, `/uninstall` 로 제거
  (`/D=` 는 **명령줄 원문에서** 읽는다 — argv 로 읽으면 공백이 든 경로가 잘린다)

**설치 폴더는 제거할 때 통째로 지운다.** 그래서 바탕화면·문서·Windows·Program Files
같은 폴더에는 설치를 거부한다. 판정은 "그 폴더 자체인지"와 "경로 끝 이름이 위험한
이름인지"를 **둘 다** 본다(끝 이름 검사를 빠뜨리면 바탕화면 설치가 통과한다).
제거는 파일 존재가 아니라 **레지스트리 InstallLocation** 을 기준으로 한다.
상대 경로 판정은 `GetFullPath` **앞에서** 해야 한다(뒤에서 하면 항상 통과한다).

릴리스 단일 exe 는 **.NET 8 데스크톱 런타임**이 필요하다.
런타임 없이 돌리려면 `--self-contained true` 로 바꾼다(대신 ~150MB).

앱이 실행 중이면 publish 가 파일 잠금으로 깨진다. `dist\SnapView.exe` 를
`SnapView.old.exe` 로 **이름만 바꾸면**(삭제 말고) 그 자리에 새로 publish 된다.

### 검증 방침

GUI 를 반복해서 띄우지 않는다. 로직 검증은 `tests/SelfTest` 로 한다 —
본체 소스를 그대로 링크해서 콘솔로 돌리므로 화면 캡처 · **WGC 창 캡처** ·
클립보드 · 휴지통 · 모자이크 · 주석 합치기 · 조절점 · 뒤집기 · 자르기 ·
